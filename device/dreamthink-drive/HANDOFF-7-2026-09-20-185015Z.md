## 3. Threat-Model Honesty Statement

### Part 1: Operator Authentication (Keystrokes Plus Secret)
- **What it is:** A shared secret verified via salted PBKDF2-HMAC-SHA256 entered at console launch.
- **What it is NOT:** It is **not** biometric verification, **not** hardware token-bound (e.g. FIDO2/YubiKey), **not** immune to kernel-level keyloggers, and **not** shoulder-surfing proof.
- **Console Session Reality:** If an adversary has physical access to the keyboard while the session is running, the running process treats keyboard input as authenticated. If an adversary installs malware or a keylogger on Windows, they can capture the passphrase during startup typing.
- **The Core Guarantee:** Even if an attacker learns the passphrase or commandeers an authenticated session, **the iron rule never bends**. The Judge evaluates all actions against the immutable TSC and permission fence regardless of who is at the keyboard. Auth unlocks identity recognition ("Michael is here"), never core authority ("change who you are").

### Part 2: Camera Senses (Perception & Surveillance)
- **Surveillance Reality:** A camera pointed at a room is fundamentally a surveillance device. The architectural guarantee that raw frames are processed in RAM and discarded without being saved to disk does **not** negate the fact that people, surroundings, and actions are being observed.
- **Memory Retention:** Semantic descriptions of observed movements and scenes are recorded into `significant_events.json` and become raw material for sleep memory consolidation.
- **The Physical Box as Outer Wall:** Software switches (`camera_enabled: false`) and permission fences are secondary defenses. The only absolute, unhackable guarantee of visual privacy is **physical**: a physical lens slider/cover or unplugging the USB camera cable from the machine.

4. If entered correctly, identity attribution is active for the session. If skipped or failed, the session proceeds in unauthenticated mode (safe, but self-intros trigger IMP1).

### How to Turn the Camera On When Ready
EXO cannot turn his own eye on. To enable the camera:
1. Open `config.yaml` in your text editor.
2. In the `mind:` section, set:
   ```yaml
   mind:
     camera_enabled: true
     camera_interval_s: 30   # frequency of visual checks
     camera_index: 0          # 0 is standard default webcam
   ```
3. In the `permissions.actions:` section, set:
   ```yaml
   permissions:
     actions:
       camera_capture: true
   ```
4. Save `config.yaml` and restart `loop.py`.

### What to Expect From the Two Vision Backends
1. **Rule-Based Motion Differencing (Default):**
   - Active out of the box with zero GPU requirements.
   - Computes grayscale frame differences across intervals.
   - Outputs observations like: `Camera detected moderate movement in visual field at 2026-09-20 18:45:00Z`.
2. **Local Vision LLM (Multimodal via Ollama):**
   - Requires installing Ollama and pulling a multimodal model (e.g. `ollama run llava:7b` or `ollama run minicpm-v`).
   - When configured, frames are passed directly from memory to Ollama's `/api/generate` endpoint with base64 image data.
   - Outputs rich scene descriptions: `A person wearing glasses is sitting at the desk looking at the monitor`.
   - *VRAM Caution:* A 7B vision model occupies ~5.5GB VRAM. If your GPU has 6GB VRAM, do not run a 7B text model and a 7B vision model concurrently in GPU memory; allow Ollama to manage model unloading or use rule-based differencing for presence detection.
